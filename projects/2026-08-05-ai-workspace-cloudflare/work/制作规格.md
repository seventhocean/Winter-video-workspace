## 舞台计划

先建立 `timeline.json`，再进入完整渲染。6 秒以上纯动画章节必须填写 `motionBeats`。

- 每个 scene 先填写一个场景模式：人物口播、复杂解释、实操与录屏或素材与全屏视觉；`layoutProfile`、构图和拓扑由 Skill 内部映射。
- 本期主要采用 `asset-visual` + `full-screen-narrative-explainer`；人脸仅在开场、效果证明、分享段和片尾以全屏或 PIP 出现。
- 叙事顺序：问题 / 12 小时限制 → 长期链接 → 电脑与手机效果 → 两步部署 → Cloudflare 关系解释 → 授权 / 上传 → 永久链接 → 手机桌面 → 分享给别人 → CTA。
- 本期按清理口播后的 17 句逐句对齐；每句至少对应一个语义动画或真实素材段，场景边界以 `edit/transcripts/8月4日.json` 的标点时间码为准。
- 无真实素材的全屏解释页补充语义辅助动画：倒计时与失效状态、临时到长期的状态迁移、云端服务器链路、一次授权流程、永久链接 24/7 状态，以及“创建—部署—长期使用”完成清单；辅助层必须解释口播，不使用无语义粒子填空。
- 人物口播重点句默认使用递进式语义舞台，至少包含一个静态重点和一个动态补充；单句和连续语义由 Skill 内部选择具体布局。
- 语义元素按口播需要添加文字、图标、图片、指标、关系图、步骤、真实素材或状态变化，不为了丰富而堆装饰。
- 复杂系统关系才进入高密度解释舞台；PPT / 录屏始终优先使用保护模式。
- `sourceFile` 通过根目录 `npm run link-asset` 链接到项目 `public/`。
- 本期最终只渲染横屏；竖屏 Composition 作为工程备用，不作为交付目标。
- HyperFrames 先输出无声透明层或无声全屏段，再作为 `hyperframes-overlay` 接入同一时间轴。
